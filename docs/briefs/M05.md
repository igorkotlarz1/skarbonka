## W skrócie
Każda zaimportowana transakcja dostaje sprzedawcę i kategorię:
- `LIDL SKLEP 1234 GLIWICE POL`, `LIDL KATOWICE` itd. to jeden sprzedawca **Lidl**; to samo dla Biedronki i Auchan;
- drzewo kategorii, sprzedawcy ze słowami kluczowymi i reguły siedzą w jednym pliku, który edytujesz sam: `backend/src/skarbonka/categorization/categories.toml`, a `uv run skarbonka seed` wczytuje zmiany;
- reguły mają priorytety (niższa liczba wygrywa), podgląd na historii bez zapisu i walidację (literówka w warunku = błąd, nie „pasuje do wszystkiego”);
- przelew między własnymi kontami (ta sama kwota, przeciwny znak, ±2 dni) trafia do „Przelewy własne” i nigdy do rozliczenia;
- ręczne przypisanie kategorii: `PUT /transactions/{id}/category` z opcją „zapamiętaj dla sprzedawcy”. Ręczna decyzja zawsze wygrywa z regułami.

## Jak edytujesz drzewo
```toml
[[category]]
name = "Jedzenie"
children = ["Zakupy spożywcze", "Przekąski", "Jedzenie na uczelni", "Restauracje"]

[[merchant]]
name = "Lidl"
keywords = ["LIDL"]
category = "Jedzenie/Zakupy spożywcze"

[[rule]]
name = "Żabka jest osobista"
priority = 10
when = { merchant = "Żabka" }
personal = true
```
Warunki reguły: `merchant`, `phrase` (całe słowo), `regex`, `amount_min`/`amount_max` (wartość bezwzględna), `account`, `weekdays` (0 = poniedziałek), `operation_kind`. Wynik: `category`, `personal` albo oba. Po zmianie: `uv run skarbonka seed` (można wielokrotnie, nic się nie dubluje).

## Orzechy do zgryzienia
- **Pole kontrahenta to zupa** (nazwa, ulica, miasto, kraj, czasem prefiks `BKG*`, `PAYU*`). Dzielę po 2+ spacjach, prefiks i kod kraju zdejmuję tylko z brzegów, numery sklepów wypadają z klucza → ✅. Czego normalizacja nie złapie, łapią słowa kluczowe sprzedawcy.
- **Ręczne decyzje kontra automat.** Alokacje `manual` i podzielone nigdy nie są ruszane przez reguły ani `seed` → ✅.
- **„Zapamiętaj dla sprzedawcy” kontra `seed`.** `seed` ustawia domyślną kategorię sprzedawcy tylko, gdy jej nie ma, więc Twoje nauczenie przetrwa ponowne wczytanie TOML → ✅. ⚠️ Zmiana nazwy kategorii w TOML tworzy nową (stara zostaje w bazie).
- **Przelewy własne** łączę zachłannie (pierwszy pasujący wpływ). Przy dwóch kontach wystarcza; przy wielu identycznych kwotach w tym samym oknie może sparować nie te nogi, ale obie i tak są „własne”.
